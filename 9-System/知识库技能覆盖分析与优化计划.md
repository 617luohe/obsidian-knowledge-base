# 知识库技能覆盖分析与优化计划

> 对 Obsidian 固定知识库做多角度、多场景、多轮深度体检，分析当前技能体系（noteall 流水线）的场景覆盖缺口，输出按推荐顺序排列的优化点清单（含优化目的、优化代价、验收方案），并作为版本管理文档驱动后续逐一落地。

---

## 一、背景与目标

固定知识库 `C:\Users\Administrator\Documents\Obsidian Vault` 由技能工程仓库 `E:\workplace\skills工程\my-skills` 的 **noteall** 统一入口控制（Intake→Curate→Publish 三阶段流水线 + Maintain 维护模式）。本次分析目标：

1. 多角度体检知识库结构现状（内容层 / 索引层 / 链接层 / 规范层 / 系统治理层）。
2. 构建多场景的知识组织与文件整理用例，逐场景核对技能覆盖。
3. 找出覆盖缺口：技能需要完善的、需要新增工具的、需要治理的文档残留。
4. 输出按推荐顺序排列的优化点清单，每条含**优化目的 / 优化代价 / 验收方案**，供后续逐一实现。

与知识库互动的其他技能：`0--claude`（CLAUDE.md 初始化）、`0--neat-freak`（CLAUDE.md/docs/memory 洁癖）、`6-最后整理`（会话收尾沉淀）、`writing-for-agents`（技能写作规范）、`leader`/`multi-worker`/`wizard` 等。

## 四、覆盖分析结论

**已充分覆盖**（日常主循环健康）：文件/URL/文本收录、会议纪要、读书阅读、日记（手触发）、长文、原子笔记、INDEX 全维护、MOC 生成审计、文件 5 维整理、Git 受控发布、会话收尾沉淀、CLAUDE.md 洁癖。

**明确缺口**（按影响排序）：
1. **系统治理一致性**（E1~E5）：文档、路由、残留技能与现行 noteall 架构脱节 —— 影响可维护性与新会话学习成本，成本最低、收益最确定。
2. **Frontmatter 合规批量审计/补齐**（D6）：30+ 文档无元数据，损害「可计算性」设计原则。
3. **断链/孤岛批量修复**（D7）：健康检查只能报告不能修。
4. **日记→永久笔记提炼**（A5/C2）：日记是原料、成品管道缺失。
5. **confidence 晋升**（D9）：渐进式完善原则未落地。
6. **确定性检查工具**（F1）：孤儿/断链/重复检测应脚本化。
7. **周期自动化**（F2/C1/C3/C4）：journal 高频但需手动触发。
8. **快速捕获**（A1）：git 脏时无法捕获，摩擦最高。

## 五、优化点清单（按推荐顺序）

> 排序逻辑：**先治理一致性（低风险、高确定性、释放新会话学习成本）→ 再补能力缺口（中风险、直接提升内容质量）→ 最后工具化与自动化（较高成本、放大效率）**。每条含优化目的 / 优化代价 / 验收方案。

### P0-1 补全 vault CLAUDE.md 路由缺口（noteall 行）

- **优化目的**：vault CLAUDE.md 是 `0-询问luohe` 路由表的常驻镜像，但工作流路由表与支撑层表均无「笔记收录/知识库整理」入口。补行后，在固定知识库项目内说「收录/整理笔记」即路由到 noteall，消除路由盲区。
- **优化代价**：极小（约 2 行文档编辑）；无风险。
- **验收方案**：vault CLAUDE.md 支撑层表出现 `笔记收录 / 知识库整理（Obsidian） → /noteall` 行；在 vault 内发起「收录一篇」由 noteall 接管。

### P0-2 清理 14 条断链技能软链

- **优化目的**：vault `.claude/skills/` 内 14 条指向已删除旧技能的断链软链污染技能发现，可能诱使模型走不存在的技能路径。清理后 `.claude/skills/` 与 skills-manager 实际技能集一一对应。
- **优化代价**：极小（删除 gitignore 的软链，不涉及 git 跟踪内容）；可随时重建。
- **验收方案**：`for l in .claude/skills/*; do [ -e "$l" ] || echo "$l"; done` 输出为空。

### P0-3 移除 vault 根下旧版 skills/ 与 agents/ 残留

- **优化目的**：`skills/`（16 个旧分解技能）与 `agents/`（3 个旧 agent 定义）已不被加载，属陈旧工作副本，与活跃技能体系并存造成「双系统」认知混乱。移除（git 历史可恢复）或归档到 `7-Sources/skills-legacy/`。
- **优化代价**：低（git rm 或移动；确认无任何活跃引用）。`agents/README.md` 声称同步 `.claude/agents/` 但该目录不存在，一并清理。
- **验收方案**：vault 根下无 `skills/` `agents/` 目录；全库 grep 无对旧技能的运行期引用（迁移对照表除外）。

### P0-4 校准文档↔技能一致性（工作流手册 + 体系设计）

- **优化目的**：`工作流手册.md` 引导用户调用 12 个已删除旧技能（slash 命令失效），`体系设计.md` 仍是 v2/v3 分解架构。更新为 noteall 统一入口表述，使文档与实际技能一一对应，新会话不必在「文档技能」与「真实技能」间辨别。
- **优化代价**：中（重写两文档的操作表与技能全景图；保留历史演进说明与迁移对照表，不删除有价值的设计思想）。
- **验收方案**：全库 grep 旧技能名，正文仅剩「迁移对照表」形式的合法引用；工作流手册每个操作步骤都能落到现行技能（noteall profile/维护模式或 0-询问luohe 路由）。

### P0-5 5-Journal/_INDEX 去 dataview + 统计刷新

- **优化目的**：全库唯一违反「静态索引、不依赖 dataview」规则处；且 vault 未装 dataview，该块在 Obsidian 渲染为纯文本。替换为静态表格并重算统计。
- **优化代价**：低（一个 _INDEX 文件编辑）。
- **验收方案**：全库 grep `dataview` 为 0；5-Journal/_INDEX 统计（总数/最后更新/本周）与实际文件一致。

### P1-1 Frontmatter 合规批量审计与修复

- **优化目的**：落实「可计算性」设计原则；修复 `7-Sources/热轧排程项目/` 约 30 篇无 frontmatter 文档，并给 noteall Maintain 增加「合规审计」模式，使全库元数据可批量检视与补齐。
- **优化代价**：中（maintain.md 增「合规审计」模式 + 一次性补齐热轧排程项目文档 + 少量历史 4-Resources 回填 status/confidence）。
- **验收方案**：合规审计命令输出全库违规清单（缺 frontmatter / 缺 tags / 缺 status / 标签格式错误 / 命名违规）；热轧排程项目文档补齐 frontmatter；Publish 前健康检查不再报缺失属性。

### P1-2 断链/孤儿批量修复模式

- **优化目的**：健康检查从「报告不阻塞」升级为「可一键修复」。断链（改链接/移除占位）与孤儿（归入 MOC 或合并/删除）两类问题的修复清单化、可确认、可执行。
- **优化代价**：中（index-keeper 健康检查输出可执行修复清单 + noteall Maintain 增加修复执行流程；需要「先确认再执行」的安全闸）。
- **验收方案**：全库断链归零或降幅 ≥90%；孤儿笔记全部进入 MOC 或明确合并/删除；修复过程遵守「修改前 grep、验断链」规则。

### P1-3 日记→永久笔记提炼管道

- **优化目的**：落实「日记是原料、永久笔记是成品」设计原则。journal profile 增加 extract 动作：从指定日记/周期提取知识点 → 生成 4-Resources 概念笔记 → 建立日记→概念双链。
- **优化代价**：中（profiles.yaml journal 增加 extract 模式 + curate 支持批量提炼 + 与 MOC 级联）。
- **验收方案**：对指定周期执行提炼，产出 ≥1 篇合规概念笔记，双链成对（日记段链接概念、概念 frontmatter 含 source 回链），MOC/INDEX 级联更新。

### P1-4 confidence 晋升维护

- **优化目的**：落实「渐进式完善」原则。Curate 更新笔记时根据成熟度（内容完整/双链成对/维护次数）提示 seed→sprout→evergreen 晋升，而非永远 `status: draft`。
- **优化代价**：低（curate.md 增晋升规则 + 更新模式检查）。
- **验收方案**：更新成熟笔记时收到晋升建议并应用；全库 confidence 分布呈现合理梯度（不再全是 seed）。

### P2-1 确定性健康检查脚本 vault_check.py

- **优化目的**：把孤儿/断链/缺属性/重复候选/统计核对检测确定性化，结果可复现、可测试，减少模型自由 grep 的漏检与误报；成为 index-keeper 健康检查与 Maintain 的底层工具。
- **优化代价**：中高（Python 脚本 + pytest，纳入 my-skills tests/，走 validate_skills 门禁）。
- **验收方案**：`pytest` 通过；脚本对当前 vault 输出报告与人工核验一致；接入 noteall 健康检查流程。

### P2-2 周期自动化（Cron 定时）

- **优化目的**：journal 是系统入口与最高频内容层，工作日自动建日报、周日自动周回顾、月末自动审计，保证习惯不断档。
- **优化代价**：低中（配置 Cron/ScheduleWakeup 定时触发 + noteall 支持无参数启动对应 profile）。
- **验收方案**：到点自动创建日报/周报；重复触发不产生重复笔记（幂等）。

### P2-3 快速捕获路径（轻量 Inbox 写入）

- **优化目的**：当前自由文本捕获走完整 noteall 流水线（需 git 干净前置），工作区脏时连想法都记不了。增加极轻量捕获分支：跳过 git 校验，仅写入 `0-Inbox/`。
- **优化代价**：低（noteall 输入识别增一个轻量分支）。
- **验收方案**：git 脏状态下「记录一个想法」成功写入 0-Inbox 并带捕获时间戳。
